## 2. 기획

**문제.** 휴머노이드·가사 로봇은 실제 집에서 사람이 손으로 하는 일 데이터가 없다. 집 영상은 얼굴·가족·집 안이 찍혀 그대로 못 팔고,
블러하면 표정·시선·손 같은 학습 가치가 사라진다. 정형 데이터로는 사람이 그 순간 어떻게 움직이고 반응했는지(실수·회복·힘듦)를 모른다.

**한 줄로.** DataCash 는 **집에 이미 있는 기기(폰·워치)만으로 촉각·시각·청각·몸 감각을 한 시간축에 모으는, 생활밀착형 고품질 로봇 데이터 양산소**다.

**해법 — DataCash.** 사용자는 집에서 미션(설거지·청소·요리…)을 찍어 보상을 받고, 로봇 회사는 개인정보가 지워진 데이터를 산다.
Meta 모델이 그 사이에서 ① 개인정보를 지우고 ② 장면을 이해해 라벨을 붙이고 ③ 그 라벨을 다른 센서로 검증하고 ④ 부족한 데이터를
미션으로 다시 요청한다.

**판매 데이터 (LeRobot v3.0 에피소드).** 가린 영상 · 손 21점·전신 33관절 · 손목 IMU · **촉각(접촉 이벤트 + 워치로 잰 쥐는 힘)** · (동의 시) 심박·피부온도 원값 ·
**조작 물체 영역(SAM 3.1)** · **단계별 언어 지시문(Muse Spark)** · 성공·실패·실수 시각 · 품질 인증서(가린 방식·동기화 오차·라벨 검증 결과·동의 기록).

**왜 '한계를 넘는가'.** 로봇 학습 데이터의 병목(실제 집, 개인정보, 라벨 비용)을 Meta 모델로 한 번에 푼다. 라벨을 그대로 믿지 않고
센서로 검증한 뒤, 큰 모델의 지식을 작은 오픈 웨이트 모델로 옮겨 비용을 낮춘다.

### 2-1. 핵심 기술 5가지 (해커톤에서 Meta 모델로 새로 짓는 것)

| # | 기술 | 하는 일 | 해커톤에서 쓰는 Meta 모델 |
|---|---|---|---|
| 1 | **가치 보존 개인정보 처리** | 블러로 지우지 않는다. 동의 안 한 사람·아이·화면·거울·액자·서류만 정확히 가리고, 동의한 참여자는 얼굴만 실존하지 않는 가상 인물로 **치환**해 표정·시선·고개·손을 남긴다. 장면마다 재식별 검사, 실패하면 그 장면만 가림 | SAM 3.1 · Muse Image · Voice Transcribe |
| 2 | **4감 데이터 동기화** (촉각·시각·청각·몸 감각) | 폰·워치에 흩어진 감각을 **ms 단위 한 시간축**으로. 손목 톡톡 + 기기 등록 보정 + 소리·움직임 상관으로 계속 맞춤, SAM 손목 추적으로 두드림 없는 동기화. 감각마다 동기화 오차를 인증서에 (2-6) | SAM 3.1 |
| 3 | **주변 기기로 만드는 촉각** | 촉각 센서 없이: **워치 능동 진동 감지**(워치가 짧게 울리고 손목의 울림을 재서 쥐는 힘을 읽음) + 영상으로 잡음·놓음 시각 + 접촉음·진동으로 내려놓음·문지름 + 말랑한 물체 변형으로 누르는 힘 (2-7) | SAM 3.1 (손·물체 영역) |
| 4 | **장면 이해와 검증된 라벨** | 가린 영상을 모델이 이해해 단계별 언어 지시문·실수 후보·장소·도구를 붙이고, 촉각·소리·물체 영역으로 **교차 검증**한 라벨만 판다 | Muse Spark 1.3 · SAM 3.1 |
| 5 | **스스로 좋아지는 수집** | 큰 모델 라벨로 오픈 웨이트 모델을 미세조정해 비용을 낮추고, 구매자 의뢰 → 미션, 부족한 사람·조건에 보상 가산 | Muse Glimmer · Muse Spark |

### 2-2. 데이터 목표 11가지

휴머노이드 회사가 사고 싶어지는 데이터의 기준 — 집에 있는 기기만으로 **촉각·시각·청각·몸 감각**을 한 시간축에 담아, '사람이 그때 어떻게 움직이고, 얼마나 세게 잡고, 어떻게 반응했나'까지.
해커톤 전 상태는 해커톤 전 시제품(비공개 저장소)의 문서에 있다.

| # | 목표 | 해커톤에서 |
|---|---|---|
| 1 | **개인정보를 치환해 사용자가 거부감 없는 앱** (최우선) | SAM 3.1 가리기 + Muse Image 가상 인물 + LivePortrait 실사 치환(MediaPipe 자르기) + 재식별 검사 |
| 2 | **촉각·시각·청각·몸 감각(자이로·심박·온도)을 싱크화한 결합 데이터** | 4감 동기화 새로 작성, SAM 손목 추적, 워치 능동 진동 촉각 (2-6·2-7) |
| 3 | **중간 동작 끊김이 적은 연속된 치환 데이터** | 영상 추적(SAM 3.1)·실사 치환으로 옆모습·추적 놓침에서 블러로 끊기는 장면 줄이기 |
| 4 | **Meta 모델로 가치 있는 장면 인식·장면 라벨링** | Muse Spark 1.3 구조화 출력, Glimmer 로 증류 |
| 5 | **생체 신호 + 본인 응답** | 심박(bpm)·HRR(%)·피부온도 변화(°C) 원값 + 미션 후 응답. 판정·조언 없음 (동의 필수, 철회 가능) |
| 6 | **손·몸 관절 라벨**을 영상과 같은 시간축으로 | 손 21점 × 양손, 전신 33관절(화면 좌표 + 3D) |
| 7 | **성공과 실패 둘 다**: 실수·재시도 장면, 성공 여부·품질 | 녹화 중 '실수했어요' + 미션 후 결과 응답 + Spark 실수 후보를 센서로 검증 |
| 8 | **사물·환경 정보**: 도구, 재질, 장소 종류, 사물 영역 | SAM 3.1 물체 영역 `observation.objects`, Spark 장소·도구·재질 |
| 9 | **다양성 관리**: 연령대·체형·집 구조·손 크기 분포, 부족한 조건은 보상으로 | 분포 대시보드, Muse Image 가상 인물도 고르게 |
| 10 | **출처·동의 증명**: 동의 기록, 가린 방식, 동기화 오차, 품질 검사, 철회 시 판매 제외 | 품질 인증서에 라벨 검증 결과까지 |
| 11 | **표준 형식과 맞춤 공급**: LeRobot 그대로, 미션·등급·센서 조합으로 | 구매자 웹, Spark 로 의뢰 → 미션 |

**읽은 것.** 라벨까지 붙은 1인칭 데이터는 시간당 $30~60(4~8만 원)이 중심이다. 여러 센서를 동기화한 데이터만 표시가 $90 이상이다.
라벨 없는 영상은 값이 빠르게 떨어진다. 그래서 우리 값은 **라벨·동기화·개인정보 처리·동의 증명**에서 나와야 한다.
처음 잡았던 분당 15,000~45,000원(시간당 90만~270만 원)은 시장의 10~40배라 버린다.

### 2-4. 경쟁 서비스·데이터와 차별점

| 구분 | 예 | 한계 | DataCash |
|---|---|---|---|
| 공개 행동 영상 데이터 (Kaggle 등, 2026-10-23 공개 API 로 확인) | 운동 영상 모음, 손씻기, Kinetics·UCF101 일부, 가정 행동 영상 | 대부분 비상업(CC BY-NC)·라이선스 불명, 출처가 YouTube 모음, **동의 언급 없음**, 센서 없음, 라벨은 행동 이름 정도 | 참여자 동의·철회 기록, 상업 판매 가능, 센서·관절·언어 라벨 |
| 연구용 1인칭 데이터셋 | Ego4D, EPIC-KITCHENS(CC BY-NC) 등 | 연구·비상업 중심, 얼굴은 블러로 지워 표정·시선 가치 손실, 원하는 미션·조건을 의뢰할 수 없음 | 블러 대신 치환, 미션 의뢰형 수집, 부족한 조건 보상 |
| 로봇 시연 데이터 | 로봇 원격조작·가정용 로봇 데이터 (유료 판매 포함) | 로봇의 동작이지 **사람의 손재주**가 아님, 수집 비용이 큼 | 사람의 실제 집안일, 폰 한 대로 수집 |
| 라벨링 외주 | 영상 라벨링 회사 | 데이터는 고객이 가져와야 하고 개인정보 처리는 고객 몫 | 수집 → 개인정보 처리 → 라벨 → 검증 → 판매까지 한 번에 |

**차별점 한 줄씩**
1. **블러가 아니라 치환** — 얼굴은 가상 인물이지만 표정·시선·고개가 남아 학습 가치가 유지된다 (해커톤 전 시제품: 블러는 자세 추정 오차 0.378 → 치환 0.101).
2. **동의 기반, 상업 판매 가능** — 동의 버전·시각·철회를 인증서에 담고, 철회하면 판매에서 뺀다.
3. **ms 동기화 등급** — 영상·소리·손목 IMU·심박을 같은 시간축으로 (해커톤 전 실기기 2~8ms).
4. **검증된 라벨** — 모델 라벨을 다른 감각으로 확인한 것만, 본인 응답이 정답.
5. **수요 기반 수집** — 구매자 의뢰가 미션이 되고, 부족한 사람·조건에 보상이 붙는다.
6. **LeRobot 그대로** — 로봇 회사가 받은 날 바로 학습에 넣는다.

### 2-6. 4감 데이터 동기화 — 집에 있는 기기만으로

후각·미각은 일반 기기로 잴 수 없어 넣지 않는다. 대신 네 감각을 주변 기기로 정확히 맞춘다.

| 감각 | 기기 (이미 있는 것) | 잡는 것 | 로봇에게 주는 의미 |
|---|---|---|---|
| **시각** | 폰 카메라 (1인칭 또는 거치), 남는 폰·태블릿을 3인칭으로 | 영상, 손 21점·전신 33관절, 물체 영역(SAM 3.1), 폰 두 대면 입체 깊이 | 무엇을 어디서 어떻게 잡나 |
| **청각** | 폰 마이크, 워치 마이크 | 소리, 접촉음(내려놓음·부딪힘·문지름·물소리), 말 | 접촉 순간, 물체 상태 |
| **촉각** | 워치(진동 모터 + 가속도계), 폰 카메라, 마이크 | 쥐는 힘, 잡음·놓음·미끄러짐 시각, 누르는 힘 (2-7) | 얼마나 세게, 언제 닿고 놓나 |
| **몸 감각** | 워치 IMU·심박·피부온도, 폰 IMU·기압·조도 | 손목 움직임, 심박·HRR·피부온도 변화(동의 시), 층·조명 | 사람의 상태를 이해하며 같이 일하기 |

**맞추는 방법 (네 단계)**
1. **공통 시계** — 기기마다 부팅 후 시계(BOOTTIME)로 기록, 와이파이·블루투스 왕복 시간으로 시계 차이를 계속 추정
2. **동시 기준점** — 녹화 시작에 손목으로 '톡톡': 한 동작이 마이크(소리)·워치 IMU(충격)·카메라(손 움직임)에 동시에 찍힌다.
   카메라가 여럿이면 폰 화면을 한 번 번쩍여 영상끼리도
3. **계속 맞추기** — 마이크끼리 소리 파형 상관(가장 정확), 영상 속 손 움직임 ↔ 손목 IMU 상관, SAM 3.1 손목 추적으로 두드림 없이도
4. **고정 지연 빼기** — 기기 등록 때 한 번 잰 카메라·블루투스 지연을 뺀다 (해커톤 전 시제품: 시계만 보정 24ms → 10ms)

**감각마다 필요한 정밀도:** 영상·소리·IMU·촉각은 수 ms, 심박·피부온도는 수백 ms. 감각마다 실제 오차를 재서 인증서에 적고,
기준을 넘는 채널은 판매 데이터에서 뺀다 (있는 척하지 않는다).

### 2-7. 촉각 — 촉각 센서 없이 주변 기기로

| 데이터 | 근거 | 범위 |
|---|---|---|
| **쥐는 힘 (계속)** | **워치 능동 진동 감지** — 워치가 1초에 한 번 0.05초쯤 짧게 울리고, 가속도계가 손목의 울림 크기·사라지는 속도를 잰다. 꽉 쥐면 손목 힘줄·근육이 단단해져 울림이 달라진다. 기기 등록 때 주방 저울을 살짝·보통·세게 눌러 사람마다 보정 | 워치를 찬 모든 녹화 (단단한 컵도) |
| **잡음·놓음·미끄러짐 시각** | 영상 — 손이 닿은 뒤 물체가 손과 같이 움직이면 잡음, 물체가 멈추고 손만 떠나면 놓음, 손에 대해 물체가 움직이면 미끄러짐 (SAM 3.1 물체 영역 + 손 관절), 들 때는 손목 IMU 로 확인 | 손과 물체가 보이는 장면 (장면 단위 약 33ms) |
| **내려놓음·부딪힘·문지름 시각** | 접촉음 + 손목 진동 (ms 단위) | 소리가 나는 동작 (조용히 집기에는 쓰지 않음) |
| **누르는 힘 (말랑한 물체)** | 스펀지 눌린 두께, 실리콘 주걱 휜 각도, 행주 짜임 — 물체를 용수철처럼 (영상, 저울로 한 번 보정) | 그런 물체를 쓴 장면 |
| 손끝 압력 분포 | — | 제공하지 않는다고 밝힌다 |

**근거와 확인.** 진동 모터를 울리고 IMU 로 반응을 재서 누르는 힘을 알아낸 폰 연구가 있다 (GripSense, UIST 2012).
손목 워치로 쥐는 힘을 읽는 것은 확실한 선례가 없는 **가설**이라 **첫날 30분 시험**으로 정한다:
워치 앱이 1초마다 짧게 울리고 직후 가속도를 기록 → 주방 저울을 세 단계로 누르거나 물병을 약하게·세게 쥠 → 울림 반응이 힘에 따라
달라지면 주력, 안 되면 쥐는 힘 칸은 빼고 나머지 촉각으로 간다.

**워치 도착(10-29) 전에 폰으로 먼저.** 폰에도 진동 모터와 가속도계가 있다.
① 폰을 손에 쥐고 짧게 울리며 약하게·세게 쥐어 반응이 달라지는지 (GripSense 를 그대로 재현 — 분석 코드를 미리 만든다)
② 남는 폰이 있으면 밴드로 손목에 묶고 워치처럼 시험 (손목 쪽 원리 확인).
워치가 오면 같은 코드로 바로 30분 시험만 다시 한다.

**걸리는 점과 대비.** 워치 진동은 초당 150~200번 떨리는데 앱이 받는 가속도 속도가 느리면 울림 크기 변화만 본다(첫날 실제 속도 확인) ·
계속 울리면 거슬리므로 짧게·필요할 때만 · 울린 구간은 IMU 데이터에 표시해 뺀다 · 손목 굵기·착용 강도에 따라 사람마다 보정.

**판매 이름.** '촉각 센서 데이터'가 아니라 **'접촉 이벤트 + 워치로 잰 쥐는 힘'** — 접촉마다 근거(어떤 감각이 맞았나)와 신뢰도,
보정 방법을 인증서에. LeRobot 채널 `observation.touch`: 접촉 확률 · 쥐는 힘(보정값) · 잡은 물체 · 접촉 단계(다가감→닿음→잡음→미끄러짐→놓음).

## 4. 전략 — "API 를 부르기만 한 게 아니다" (기술 깊이 점수)

1. **개인정보 순서.** 원본은 폰·우리 서버 밖으로 보내지 않는 것이 기본. API 에는 가린 프레임·구간만 보낸다.
   SAM 3.1 처럼 가리기 전 영상이 필요한 단계는 **본인(동의자)만 나오는 녹화**로만 시연한다. 소리도 개인정보 발화를 끈 뒤 보낸다.
2. **라벨은 센서로 검증한다.** Spark 가 "3.2~5.0초 팬에 기름 두르기"라고 하면 같은 시각 손목 IMU·소리 사건·SAM 물체 영역(팬이 손 근처에
   있었나)과 맞는지 본다. 맞은 라벨만 `verified` 로 판매 데이터와 학습에 쓴다. 사용자의 '실수했어요' 표시와 Spark 실수 후보도 교차 확인.
3. **비싼 모델은 애매할 때만.** 자체 판정(Glimmer/작은 모델) 확신이 낮은 구간만 Spark 에 묻는다 → API 호출 수 대비 정확도 곡선을 보여 준다.
   $150 크레딧 안에서 돌아가게 하는 설계이기도 하다.
4. **큰 모델이 가르치고 작은 모델이 배운다.** 검증된 Spark 라벨로 Glimmer 를 SFT → 고정 시험 세트에서 좋아질 때만 새 버전.
   해커톤 끝에 "API 없이 우리 서버에서 라벨링하는 오픈 웨이트 모델"이 남는다.
5. **숫자로 증명.** 첫날 고정 시험 세트를 만들고(본인 녹화 + 라이선스 확인된 공개 영상), 모든 단계를 같은 세트로 전·후 비교한다.
6. **수요가 수집을 이끈다.** 구매자가 원하는 데이터 → Spark 가 미션·촬영 상황으로 → 부족한 조건(연령대·체형·장소)에 보상 가산.

### 7-1. 마지막 20초 — 구매자 활용 예시: 사람을 이해하며 같이 집안일을 하는 휴머노이드

구매 고객 후보 중 **휴머노이드·피지컬 AI**를 예시로 쓴다. 헬스케어(AI 건강 조언)·스포츠 분석/코칭은 공지의 금지 항목과 겹쳐 쓰지 않고,
AR/VR·메타버스는 발표 슬라이드에 한 줄만 넣는다.

**장면 (시뮬레이터, 한 가지 집안일).** 사람과 휴머노이드가 함께 **빨래 바구니 나르기**(또는 대청소)를 한다.
로봇은 우리 데이터로 학습한 작은 모델로 "이 작업을 계속하면 사람의 심박이 얼마나 오를지"를 미리 보고, 높을 것 같으면
**로봇이 무거운 쪽을 더 맡거나 속도를 늦춘다.** 사람에게 건강 조언을 하지 않는다 — 바뀌는 건 로봇의 행동뿐이다.

| 화면 (3분할) | 내용 |
|---|---|
| 왼쪽 | 우리 데이터의 가린 영상 (사람이 바구니를 드는 장면) |
| 가운데 | 시뮬레이터 속 휴머노이드: 사람 동작(전신 33관절)을 재생한 '사람' 옆에서 로봇이 함께 나름 |
| 오른쪽 | 같은 시간축 그래프: 실제 심박(데이터) · 로봇이 예상한 심박 · 로봇의 분담 비율이 예상에 따라 바뀌는 순간 |

같은 장면에서 로봇은 데이터의 **쥐는 힘(촉각)** 을 보고 바구니 손잡이를 사람과 비슷한 힘으로 잡는다 — 4감이 한 장면에 다 쓰인다.

**만드는 것 (작게)**
1. 예측 모델: 입력 = 앞 몇 초의 손목 IMU·몸 관절·작업 단계(Spark 지시문), 출력 = 몇 초 뒤 HRR(%) 변화. 생체 등급 에피소드로 학습,
   다른 사람·다른 날 녹화로 검증한 오차(%p) 하나를 화면에 띄운다.
2. 시뮬레이터: MuJoCo + 공개 휴머노이드 모델(라이선스 확인), 사람 관절 → 관절 각도 리타기팅으로 재생, 로봇은 분담 비율에 따라 속도·들 무게를 바꾸는 단순 규칙.
3. 맺는 말: "인간의 한계를 무시하고 일하는 로봇이 아니라, 사람을 이해하며 같이 일하는 로봇. 그 이해를 가르치는 데이터가 DataCash 입니다."

**필요한 데이터와 대비**
- 손목 기기(갤럭시 워치)로 찍은 **생체 등급 녹화**가 있어야 한다. 해커톤 전 워치를 반납했으므로 **첫 주 안에 워치를 구해**
  빨래 나르기·대청소 미션을 여러 번(다른 날·다른 강도) 찍는다. 생체 동의(bio)를 받은 본인 녹화만 쓴다.
- 워치를 못 구하면: 예측 대상을 심박 대신 **미션 후 본인 응답(힘듦 1~5)** 으로 바꾸고, 로봇은 같은 방식으로 분담을 바꾼다.
- 예측 모델·시뮬레이터 코드는 해커톤 중 새로 작성. 정확도가 낮으면 숫자를 그대로 밝히고 "데이터가 쌓일수록 좋아진다"(학습 곡선)로 보여 준다.
