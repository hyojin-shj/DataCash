# 라벨 정확도 — 한눈에 보기 (2026-10-30)

폰과 워치만으로 로봇이 배울 만한 데이터를 만든다는 것이 DataCash 의 핵심이다.
그러려면 "라벨이 얼마나 맞는가"를 숫자로 말할 수 있어야 한다. 이 문서는 10-30 하루 동안 한 일을 요약한다.
자세한 표와 실험은 [label_eval.md](label_eval.md) 에 있다.

## 1. 문제: 지금까지의 숫자는 정확도가 아니었다

- 앱·웹에 쓰던 "검증 92%", "Spark 1.3 ↔ Spark Open 일치 73%"는 **정답과 비교한 값이 아니다.**
  모델끼리 맞는지, 우리 규칙을 통과했는지를 본 것이다.
- 정답을 직접 만들려면 사람이 영상을 0.1초 단위로 보며 단계를 나눠야 한다 — 너무 비싸고 느리다.

## 2. 방법: 사람이 붙인 공개 정답으로 채점

- **EPIC-KITCHENS-100**: 1인칭 주방 영상에 사람이 동작 구간(시작·끝·동사)을 붙인 공개 데이터.
  - 라이선스가 CC BY-NC 4.0 이라 **내부 확인용으로만** 쓴다. 학습·판매·정답 예시에는 쓰지 않는다.
  - 받기는 Hugging Face 미러에서 (원 서버가 너무 느렸다).
- 동작이 촘촘한 60초 구간을 골랐다.
  - **방법 고르기용 8구간**(정답 380단계)과, 방법을 다 고른 뒤에만 여는 **새 8구간**(271단계, 다른 참여자·부엌).
  - 고른 구간에서만 좋아 보이는 변형을 거르기 위해서다. 실제로 하나(물체 상태 규칙)가 여기서 걸러졌다.
- 우리 라벨 흐름에 그대로 넣고, EPIC 동사와 우리 동작을 같은 거친 묶음(take · put · articulate · wash · pour · move)으로 바꿔 맞댔다.
- 지표: 장면 정확도(0.1초마다 같은 동작인가), F1@10/25/50, 순서 점수, 경계 오차(ms).
- 같은 설정을 다시 돌려도 3~5%p 흔들린다. 그 안쪽 차이는 믿지 않는다.

코드
- 채점: `datacash/understand/score.py`
- 실험: `scripts/eval_epic.py` (`pick` → `fetch` → `run`/`exp` → `score`/`exp_score`, `--set test` 는 새 구간)
- 경계 다듬기: `datacash/understand/refine.py`

## 3. 처음 잰 결과

- 장면 정확도 **35~37%**, 경계 오차 **355ms**.
- **두 모델이 같게 본 단계 중 실제로 맞는 것은 39% 뿐.** "두 모델 일치"는 정답의 증거가 못 된다.
- 2차 검증(Spark Open)은 +2%p 에 그쳤다.
- 가장 큰 오류는 시각: 집기·놓기가 0.6~0.8초마다 번갈아 나오는데 경계가 수백 ms 밀려 서로 뒤바뀐다.

## 4. 올린 방법

| 바꾼 것 | 효과 (새 8구간) | 처리에 넣었나 |
|---|---|---|
| 60초를 한 번에 → **20초씩 잘라 0.5배속으로** 보내기 | 장면 36% → **47%**, 경계 430 → 230ms | 넣음 |
| **경계 장면 고르기**: 경계 앞뒤 장면 8장 중 "다음 동작이 시작된 첫 장면"을 Spark Open 이 고름 | 경계 230 → **182ms** (정확도는 그대로) | 넣음 |
| 동작에 **열기·닫기** 추가 | 열기·닫기류 37% → 47~49% | 넣음 (번호 18·19, 예전 번호는 그대로) |
| 10초 자르기, 세 번 다수결 | 20초보다 낫지 않거나 비용 대비 작음 | 안 넣음 |
| 손이 멈춘 순간으로 경계 맞추기 | EPIC 에서는 효과 없음 (머리 카메라·쉬지 않는 손) | 코드만 (`refine.snap`) |
| 물체 상태로 이름 정하기 규칙 | 고른 구간 +9%p, **새 구간 0** — 우연 | 안 넣음 |
| 씻기·젓기·자르기 추가 | 효과는 대부분 EPIC 에만 많은 '씻기' | 안 넣음 |

지금 처리(`datacash/jobs.py`): Spark 1.3 에 20초 × 0.5배속(`understand_chunked`) → Spark Open 2차 검증 → 경계 장면 고르기(`refine.pick`).
결과는 `job.json` 의 `boundaries` 에 남는다.

## 5. 지금 수준

- 새 구간 기준 **장면 정확도 47%, 경계 오차 182ms** (처음: 36%, 430ms).
- 들고 옮기는 부분을 우리처럼 'transport' 로 따로 나누는 규칙 차이를 맞음으로 치면, 씻기·붓기를 뺀 정확도는 **59%**.
- EPIC 은 우리 녹화보다 어렵다 (머리 GoPro, 빠르고 겹치는 요리 동작, 미션 설명 없음). 우리 녹화(컵 옮기기·티슈 뽑기)에서는 이보다 높을 가능성이 크다 — 다만 아직 재지는 못했다.
- 비용: 구간 1분에 Meta API 약 $0.09 + Spark Open 약 $0.26.
- 오늘 실험 전체: Meta API 약 $9.9, Spark Open 약 $5.3 (추정).

## 6. 남은 것

- **동작 이름 혼동**(집기 ↔ 놓기)은 질문을 바꿔서는 더 줄지 않았다.
  다른 길이 필요하다: 우리 라벨로 학습, 더 큰 모델, 또는 우리 녹화의 센서(손목 IMU·접촉음으로 물체가 손에 들렸는지).
- **정답 예시 고르기 기준**: 지금은 "두 모델 일치 + 감각 검증"을 통과한 단계를 다음 녹화의 정답 예시로 쓴다.
  일치가 정답의 증거가 아니니, 이 기준을 바꿔야 한다.
- **우리 녹화의 정확도**: 손 멈춤·접촉음·IMU 로 경계를 맞추는 효과도 포함해, 우리 녹화 몇 편의 정답이 있어야 잴 수 있다.
- **다른 감각**(청각·촉각·움직임·생체)은 이번에 정답과 맞대 재지 않았다. 이번 채점은 영상 단계 라벨만 다룬다.
