# 모델 진화 — 검증된 라벨로 우리 동작 모델을 키운다

코드: `datacache/evolve.py` · 테스트: `tests/test_evolve.py` · 운영자 API: `GET /api/admin/evolve` · 기록: `data/evolve/registry.json`

## 흐름

```
녹화 처리 끝 ─▶ Muse Spark 단계 라벨 ─▶ 감각으로 검증 (접촉·소리·손목·경계)
                                          │ 검증된 단계의 장면만 정답으로
                                          ▼
                서버가 뒤에서 다시 학습 (녹화가 늘 때마다 새 버전 v1, v2, …)
                                          │ 녹화 하나씩 빼고 맞혀 보기 · 성장 곡선 · 기준선
                                          ▼
       준비됨? (세부 동작 macro F1 ≥ 0.8 · 학습 녹화 ≥ 20개)
          └ 예 → 다음 녹화에서 확신 ≥ 0.7 이면 Spark 를 부르지 않고 우리 모델이 단계를 쓴다
          └ 아니오 → 지금처럼 Spark (그 결과가 다시 학습 재료가 된다)
```

## 무엇을 보고 배우나 (이 맥에서 공짜로 뽑은 것만)

- 손 21점 × 2: 손목 위치, 손 크기, 손을 편 정도, 엄지·검지 간격
- 손 ↔ 가장 가까운 물체(SAM 상자) 거리와 그 물체 높이
- 폰·손목 IMU 움직임 크기, 소리 세기·소리 사건
- 앞뒤 0.17초·0.5초의 평균과 변화량, 녹화 안 상대 위치
- **쓰지 않는 것:** 단계 경계·검증 표시·접촉 단계 — 라벨에서 나온 값이라 답을 미리 보는 셈

모델은 그래디언트 부스팅(sklearn)이고, 확률을 앞뒤 9장면으로 평균한 뒤 6장면보다 짧은 구간은 이웃에 붙인다.
두 수준으로 배운다: **세부 동작**(reach·grasp·lift·pull·…·release)과, 미션이 달라도 공통인 **큰 단계 4가지**(다가가기·잡고 다루기·내려놓기·기타).

## 첫 버전 (v1, 10-27 저녁, 점심 녹화 4편 · 검증된 장면 984개)

| 수준 | 정확도 | 기준선 (가장 많은 동작만 찍기) | macro F1 |
|---|---|---|---|
| 세부 동작 9가지 | 0.171 | 0.265 | 0.101 |
| 큰 단계 4가지 | 0.686 | 0.666 | 0.396 |

성장 곡선 (큰 단계, 남은 녹화를 맞힌 정확도): 학습 녹화 1개 0.40 → 2개 0.73 → 3개 0.76 (기준선 0.67 을 넘기 시작).

**솔직한 해석:** 녹화 4편·미션 2가지로는 세부 동작을 배우지 못한다(기준선 아래). 큰 단계는 데이터가 늘수록 오르는 모습이
보이기 시작했다. 필요한 것은 모델이 아니라 데이터 양 — 녹화가 쌓일 때마다 서버가 자동으로 다시 학습해 곡선을 이어 간다.
Glimmer(30B)를 직접 다시 학습시키는 것은 이 맥(32GB)과 지금 데이터 양으로는 하지 않았다.
